# 阶段一 · 小点 2：Java 17 / 21 / 25 语言特性

> 所属：阶段一 Java 语言深化与 JVM 体系
> 定位：用现代 Java 写业务代码，并理解语言的演进方向。目标版本是 Java 25 LTS——新特性不是炫技，record / 模式匹配 / 虚拟线程已经是生产代码的主流写法；还在写 JDK 8 风格的代码，就像 2026 年还在用 ES5 写 React。

## 快速入门

> 本节为「现代 Java 速览」：先认识这几个新语法点写得有多简、解决什么问题；「底层怎么实现、什么时候别用」留在正文提高部分。

### 本讲核心关键词速查

| 关键词 | 一句话大白话 | 例子 |
|-|-|-|
| record | 一行声明「不可变数据类」的语法糖（字段+构造器+getter+equals 全自动） | `record Point(int x, int y) {}` |
| sealed（密封类） | 限制「只有这几个子类能继承我」 | `sealed interface Shape permits Circle, Rect {}` |
| 模式匹配（switch） | 在 switch / instanceof 里直接解构类型和 record 字段 | `if (shape instanceof Circle c) ...` |
| 虚拟线程 | JVM 管理的轻量线程，阻塞不占 OS 线程；「一请求一线程」也能扛海量并发 | `Thread.startVirtualThread(...)` |
| ScopedValue | 有界作用域的上下文值（线程私有、自动清理） | `ScopedValue.where(TRACE_ID, id).run(...)` |
| var | 类型推断：让编译器根据赋值推断类型 | `var list = new ArrayList<String>();` |

### 本讲在解决什么问题

- **问题**：老 Java 用大量样板代码（一个只装数据的类要手写 getter/equals/toString），且 switch、instanceof 用法死板。新特性让代码**更短、更贴近类型安全**。
- **你要带走的一句话**：`record` 是用来**替代样板数据类**的（等价于 Lombok 的 `@Value`，但语言原生支持）；`模式匹配` 是让「类型判断 + 取值」一步到位；`虚拟线程` 是让 Java 也能像 Go 一样「一个请求一个线程」还不怕并发爆炸。

### 最简可运行示例（照抄能跑）

```java
// record: 一行定义不可变数据类(自动生成 构造器/getter/equals/hashCode/toString)
public record Order(String orderNo, double amount) {}

// 模式匹配 switch: 按类型解构, 不用 cast 就能直接用字段
public String describe(Object o) {
    return switch (o) {
        case Order(String no, double amt) -> "订单 " + no + " 金额 " + amt;   // 解构出 no/amt
        case String s -> "字符串 " + s;
        default -> "未知";
    };
}
```

> 代码备注（逐行解释）：
> - `record Order(String orderNo, double amount) {}`：编译器自动生成构造器、`orderNo()`/`amount()` 访问器、`equals` / `hashCode` / `toString`。比手写一个 class + Lombok 更干净。
> - `case Order(String no, double amt)`：模式匹配里直接「解构」record 的字段到 `no`、`amt` 两个变量，不用手动 `instanceof` + `cast`。
> - `default ->`：switch 表达式必须有穷尽分支或 default（否则编译报错）。
> - 注意 record 的访问器是 `order.orderNo()`，**不是** `order.getOrderNo()`——这是和普通 JavaBean 最大的习惯差异。

### 关键特性 / 用法说明

| 特性 | 干什么 | 最易踩的坑 |
|-|-|-|
| `record` | 定义不可变数据载体 | 不能 `extends` 类（隐式继承 Record）；访问器是 `字段名()` 不是 `getXxx()` |
| `sealed` + `permits` | 封锁继承层级 | 子类可选 `final` / `sealed` / `non-sealed` |
| switch 模式匹配 | 类型判断 + 解构一步到位 | 需穷尽所有分支或加 `default` |
| `var` | 类型推断 | 只在编译器能推断时用；别用在公开 API 签名上（丢失可读性） |
| `Thread.startVirtualThread` | 开一个虚拟线程 | 虚拟线程廉价；CPU 密集任务别用它 |
| `ScopedValue` | 线程私有上下文 | 与 ThreadLocal 相比不可变 + 自动清理 |

### 常用约定 / 命名提示

- **目标版本**：本计划以 **Java 25 LTS** 为基线——record / 模式匹配 / 虚拟线程都是生产可用的主流写法。
- **看到老 JDK 8 风格**：能自动「翻译」成新写法（如 `new ArrayList<>()` 可用 `var`、匿名类可用 Lambda、样板类可改 record）。
- **新特性 ≠ 炫技**：record 用于数据载体、模式匹配用于分支解构、虚拟线程用于 IO 密集——用到点子上才是好代码。

## 学习内容详情

### 1. Java 17：密封类

**密封类（sealed）**：用 `permits` 子句显式声明「只有这几个类能继承我」——把封闭的继承层级编码进类型系统。类比：TypeScript 的联合类型 `type Shape = Circle | Rect` 给了「取值范围」的穷尽检查，sealed 就是 Java 在类体系上的对应物。

```java
// sealed + permits: 白名单式继承 —— 只允许 Circle / Rect 实现 Shape
// 没在 permits 里的类想 implements Shape? 编译直接报错
public sealed interface Shape permits Circle, Rect {}

// 子类必须三选一: final(到此为止) / sealed(继续封闭) / non-sealed(重新开放)
public record Circle(double radius) implements Shape {}        // record 天生 final
public record Rect(double width, double height) implements Shape {}
```

**non-sealed 一行示例**：当层级中途需要重新开放扩展时，子类可声明 `non-sealed` 重新放开继承——自己仍要进 `permits`，但从它往下任何人都能继承：

```java
public non-sealed class OpenShape implements Shape {}   // OpenShape 之下的子类无需进任何 permits
```

价值在哪？配合 switch 模式匹配（下文）——**编译器知道 Shape 只有两种实现**，漏写一个分支编译不过。新增 `Triangle` 时，permits 加一行 + 所有 switch 处编译报错提醒你补分支——这是「新增类型不漏改逻辑」的类型级保障。

### 2. Java 21：现代业务代码三件套

#### 2.1 record：不可变数据载体

**record**：一行声明「字段 + 构造器 + getter + equals + hashCode + toString」的不可变数据类——替代 Lombok 的 `@Value`，且是语言级支持（没有编译期插件依赖）。

```java
// 一行 = 老写法的 40 行; 字段隐含 final, 天生不可变、天生线程安全
public record OrderItem(String sku, int quantity, BigDecimal price) {}

var item = new OrderItem("SKU-001", 2, new BigDecimal("19.90"));
System.out.println(item.sku());          // 注意: 访问器是 item.sku() 不是 getSku()
System.out.println(item);                // 自动 toString → OrderItem[sku=SKU-001, quantity=2, price=19.90]

// 两个相同字段的 record 自动 equals —— 值语义, 对比 TS 的结构相等
System.out.println(item.equals(new OrderItem("SKU-001", 2, new BigDecimal("19.90"))));  // true
```

与普通类的三个差异（**必背**）：① 字段全部 final 不可变；② 自动生成 equals/hashCode/toString（按值判等，非按引用）；③ 不能继承别的类（隐式继承 `java.lang.Record`），但可以实现接口。

#### 2.2 record 模式 + switch 模式匹配

**模式匹配**：在 `instanceof` / `switch` 里「按类型匹配 + 自动拆解字段」——告别 if-else instanceof 链和手动强转。

```java
// ---- 反面教材: JDK 8 风格的 instanceof 地狱 ----
static double areaBad(Shape s) {
    if (s instanceof Circle) {
        Circle c = (Circle) s;                       // 手动强转, 三行才能干一件事
        return Math.PI * c.radius() * c.radius();
    } else if (s instanceof Rect) {
        Rect r = (Rect) s;
        return r.width() * r.height();
    } else {
        throw new IllegalArgumentException("未知形状");
    }
}

// ---- 正面教材: switch 模式匹配 + record 解构 ----
static double area(Shape s) {
    return switch (s) {
        case Circle(double radius) -> Math.PI * radius * radius;   // 解构: 直接取出字段
        case Rect(double w, double h) -> w * h;
        // 没有 default! 因为 Shape 是 sealed, 编译器知道分支已穷尽
        // 哪天加了 Triangle 并 permits, 这里会直接编译报错提醒补分支
    };
}
```

**when 守卫**：`case` 可以追加条件，进一步收窄匹配范围：

```java
static String classify(Shape s) {
    return switch (s) {
        case Circle c when c.radius() > 100 -> "大圆";
        case Circle c                        -> "小圆";
        case Rect r when r.width() == r.height() -> "正方形";    // 守卫在前, 普通分支兜底
        case Rect r                          -> "长方形";
    };
}
```

#### 2.3 虚拟线程（GA）

JDK 21 转正的重量级特性，详细展开在第 7 讲并发编程。这里先建立一句话认知：**轻量级线程，阻塞它不占 OS 线程**——「一请求一线程」的同步写法也能扛海量并发，不再被迫全链路响应式。

```java
// JDK 21+: 直接创建, 无需池化
Thread.startVirtualThread(() -> System.out.println("跑在虚拟线程上"));

// try-with-resources 形态的 executor: 每任务一个虚拟线程
try (var exec = java.util.concurrent.Executors.newVirtualThreadPerTaskExecutor()) {
    exec.submit(() -> "IO 任务");
}   // close() 自动等待任务完成
```

### 3. Java 25 新特性

#### 3.1 Scoped Values（转正）：ThreadLocal 的现代替代

**ScopedValue**：有界作用域的不可变上下文值——绑定只在一段代码范围内有效，范围内直接读，出了范围自动消失。解决 ThreadLocal 的两大痛点：可变（谁都能 set）+ 忘记 remove 导致泄漏（第 5 讲）。

```java
import java.lang.ScopedValue;   // 注意: ScopedValue 在 java.lang 包, 不是 java.util.concurrent

public class RequestContext {
    // 静态的 ScopedValue 容器: 网关里塞 TraceId, 全链路任何代码都能读
    private static final ScopedValue<String> TRACE_ID = ScopedValue.newInstance();

    public static void handle(String traceId) {
        ScopedValue.where(TRACE_ID, traceId)     // 绑定: 只在这个 lambda 作用域内有效
            .run(() -> {
                serviceLayer();                  // 深层调用链里直接读, 不用层层传参
            });
        // run() 返回后绑定自动解除 —— 没有忘记 remove 这回事
    }

    static void serviceLayer() {
        System.out.println("trace_id=" + TRACE_ID.get());   // 读当前绑定值
    }
}
```

与 ThreadLocal 的两个关键优势（**必背**）：① **不可变 + 自动清理**——绑定在代码块结束自动失效，从根上消灭泄漏；② **与虚拟线程 / 结构化并发协同**——子任务（子虚拟线程）自动继承父作用域的值，ThreadLocal 做不到。

#### 3.2 结构化并发（预览，JEP 505）

**结构化并发**：把一组并发子任务当作一个工作单元管理——任一失败整体取消，生命周期像结构化编程的控制流一样清晰。类比你熟悉的 `Promise.allSettled` + AbortController 的组合，但是语言级 + 作用域级自动取消。

```java
// 预览特性: 需要 --enable-preview 编译运行, 语法可能微调
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.Future;

Response handle() throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        // 两路并发: 像声明两个局部变量一样声明子任务
        Future<User>  user  = scope.fork(() -> fetchUser());     // 调用户服务
        Future<Order> order = scope.fork(() -> fetchOrder());    // 调订单服务

        scope.join()           // 等全部完成
             .throwIfFailed(); // 任一子任务失败 → 整体抛异常, 另一路自动取消(不浪费)

        return new Response(user.resultNow(), order.resultNow());
    }   // scope 关闭时保证没有泄漏的子任务
}
```

#### 3.3 紧凑 main 与模块导入（版本注意）

```java
// 完整写法的对比 —— 紧凑 main: 单文件脚本 / 学习代码的福音
// 老写法: public class Hello { public static void main(String[] args) { ... } }
void main() {                                  // 无类声明、无 static、无 String[] args
    System.out.println("Hello!");
}

// 模块导入: 一次导入整个模块, 告别 20 行 import java.util.*
import module java.base;
```

> 版本提醒：`void main()` 是 **JDK 21** 起就 GA 的便捷写法（JEP 445）；`import module java.base;` 是 **JDK 23 预览**（JEP 476）——两者都是「新写法的趋势」，不是 Java 25 才引入的。25 真正新增的是 Scoped Values 转正与结构化并发（预览）。

#### 3.4 Stable Values（预览，了解即可）

延迟初始化 + 不可变 + JVM 可深度优化的值——为 Valhalla 值类铺路的性能原语。当前阶段知道概念即可，写业务代码用不上。

### 4. 演进路线图（了解即可）

- **Valhalla 值类**：JDK 28 起预览。目标是让「没有身份语义的对象」（两个字段相同的值对象就是相等，不需要唯一标识）走值化存储路径——减少内存占用（不再有对象头 + 指针间接寻址），数组存值对象就像存 int 一样紧凑。
- 学习策略：路线图层面的认知够用，写代码以当前 LTS（25）已 GA 的特性为准；预览特性（结构化并发 / Stable Values）跟踪 JEP 动态即可。

### 坑点提醒

- **record 的访问器是 `item.sku()` 不是 `getSku()`**——从 Lombok / 老代码切过来最容易手滑；MyBatis-Plus 等框架映射 record 时也要确认版本支持。
- **switch 模式匹配的 null 分支**：`case null` 需要显式写（JDK 21+ 允许），否则传入 null 直接抛 NPE 而不是走 default。
- **sealed 子类必须与父类同包**（或同一编译单元可省略 permits）——跨包拆分子类时注意模块边界。
- **ScopedValue 在线程池里「漂移」**：它跟随的是「当前线程的调用栈作用域」，把 `ScopedValue.get()` 塞进池化线程的 Runnable 里读不到绑定值——结构化并发的 fork 才保证继承。
- **预览特性别进生产**：结构化并发需要 `--enable-preview`，且语法在后续版本可能调整。
