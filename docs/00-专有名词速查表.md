# 专有名词速查表

> 按主题集中解释大纲与正文中出现的专有名词，遇到陌生词随时回查。术语按「所属阶段」分组，括号内是该词详细展开所在的小点。

## Java 语言与 JVM（阶段一）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| JVM / JDK / JRE | JVM 是跑字节码的虚拟机；JDK = JVM + 编译器等开发工具；JRE = JVM + 基础类库（运行环境） |
| JIT | 即时编译：热点代码先解释执行，跑热了再编译成本地机器码，越跑越快 |
| 类加载器 / 双亲委派 | 类加载的分层机制；先委托父级加载，保证核心类不被篡改、只加载一次 |
| 类型擦除 | 泛型只活在编译期，运行时 `List<String>` 和 `List<Integer>` 是同一个类 |
| PECS | 通配符口诀：Producer Extends（只读用 `? extends`），Consumer Super（只写用 `? super`） |
| 动态代理（JDK / CGLIB） | 运行时生成「替身对象」拦截方法调用——Spring AOP / MyBatis Mapper 的底层机制 |
| happens-before | JMM 的可见性规则：A hb B 意味着 A 的结果对 B 可见（不是时间先后） |
| volatile | 保证可见性 + 禁止重排，**不保证原子性**（`i++` 照样丢） |
| 锁升级 | synchronized 从轻量级（CAS 自旋）到重量级（内核互斥）的膨胀过程；偏向锁已废弃 |
| AQS | JUC 锁工具的公共底座：一个 volatile state + 一条等待队列 |
| CAS | CPU 原子指令「值是 A 就换成 B」，无锁编程的地基 |
| 虚拟线程（Loom） | JVM 调度的轻量线程，阻塞不占 OS 线程；IO 密集并发的新答案 |
| Pinning | 虚拟线程在 synchronized 块内阻塞时被「钉」在载体线程上无法释放的坑 |
| ThreadLocal / ScopedValue | 线程私有上下文变量；ScopedValue 是 ThreadLocal 的现代替代（不可变+自动清理，JDK 25 起正式可用） |
| fail-fast | 集合迭代时检测到结构修改立即抛异常——是错误检测，不是并发保护 |
| 不可变对象 / record | 字段全 final、按值判等的数据载体，天生线程安全 |

## Spring 生态（阶段二）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| IoC / DI | 控制反转 / 依赖注入：对象创建装配交给容器（≈ NestJS 的 @Injectable 体系） |
| Bean | 被 Spring 容器管理的对象实例 |
| BeanPostProcessor | 容器级「加工流水线」，所有 Bean 初始化前后各插一手；AOP 代理在这步生成 |
| 三级缓存 | Spring 解决 setter 注入循环依赖的机制；构造器注入的循环无解 |
| AOP | 面向切面：把事务 / 日志等横切逻辑集中声明，运行时代理织入 |
| @Transactional 失效 | 事务切面失效的五大场景：自调用 / 非 public / 异常被吞 / 传播错配 / 多线程 |
| 事务传播行为 | 嵌套事务边界的规则（REQUIRED 默认加入 / REQUIRES_NEW 独立新事务） |
| starter | 一组依赖 + 一份自动配置的打包，「引入即生效」 |
| 自动装配 | @EnableAutoConfiguration 按类路径与条件注解决定装配什么 |
| @Conditional | 条件装配注解族：类存在 / Bean 缺失 / 配置开关满足才生效 |
| BOM | 依赖版本清单（dependencyManagement import），统一全家桶版本 |
| Actuator | Boot 的生产端点：健康检查 / 指标 / 环境信息（K8s 探针与 Prometheus 的数据源） |
| AOT / Native Image | 提前编译：GraalVM Native Image（毫秒启动）或 Leyden AOT 缓存（启动提速约 40%+，因应用而异） |
| MDC | 日志诊断上下文：往里面塞 TraceID，同一请求的日志全部带同一标记 |
| WebFlux / Reactor | 响应式技术栈；Mono（0-1 个值）/ Flux（0-N 个值）是它的类型系统 |
| 背压（Backpressure） | 消费者告诉生产者「我只能消化这么多」的流控机制 |
| JWT | 签名防篡改的自包含 token；**不加密**（Payload 是 Base64）且难以撤销 |
| OAuth 2.1 / OIDC / PKCE | 授权协议 / 其身份层 / 防授权码截获的校验机制 |
| RBAC / ABAC | 按角色 / 按属性判权限；RBAC 管功能入口，ABAC 管数据范围 |
| 切片测试 | 只加载容器一部分的测试注解（@WebMvcTest / @DataJpaTest） |
| Testcontainers | 用真实 Docker 容器做集成测试，消灭内存库的「假绿色」 |

## 数据持久化与中间件（阶段三）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| InnoDB | MySQL 默认存储引擎（事务 / 行锁 / MVCC 都在它这层实现） |
| 聚簇索引 / 二级索引 | 主键索引叶子存整行；二级索引叶子存主键，查完要回表 |
| 回表 / 覆盖索引 | 二级索引查到主键再回聚簇索引取整行；查询列全在索引里则免回表 |
| B+ 树 | 磁盘友好的高扇出树：非叶节点不存数据、叶子成链表支持范围查 |
| MVCC / ReadView | 多版本并发控制：读不加锁靠版本链；快照视图决定哪个版本可见 |
| 间隙锁 / Next-Key Lock | 锁「记录之间的空隙」防插入，RR 级别防幻读的核心 |
| GTID | 全局事务标识，替代「日志文件+位点」的主从复制管理 |
| ShardingSphere | 国内主流分库分表中间件：JDBC 客户端形态（增强版驱动，无额外跳）/ 代理形态（独立代理层，多语言友好） |
| 分片键 | 决定数据落在哪个分片的列（如 user_id）；选错 = 大量查询退化为「广播全分片」 |
| 广播表（公共表） | 字典/配置类全局只读小表：每个分片存一份完整副本，join 时不广播、不拆 |
| 虚分片 | 用大量逻辑分片映射到少量物理库；扩容只需挪逻辑分片到新库，数据不动——规避「重算模」式全量迁移 |
| 游标分页 | 传「上一页最后一条的排序键」下一页，规避深 offset——分片库上深分页的通解 |
| N+1 问题 | JPA 查 1 次列表 + 每行懒加载关联各查一次；用 @EntityGraph / JOIN FETCH 解 |
| RDB / AOF | Redis 快照持久化 / 追加日志持久化；混合持久化两者兼得 |
| 哨兵 / Cluster | Redis 自动故障转移 / 分片集群（16384 槽，客户端错节点收 MOVED） |
| Redisson / 看门狗 | Redis 分布式锁客户端；看门狗自动续期防业务没跑完锁先过期 |
| RedLock | 多实例 Redis 锁算法，存在学界争议——生产单实例 Redisson 通常够用 |
| 布隆过滤器 | 「一定不存在 / 可能存在」的概率结构，挡缓存穿透 |
| ISR | Kafka 与 leader 保持同步的副本集合；acks=all 即等 ISR 全确认 |
| 消费者组 / 重平衡 | 组内消费者均分分区；成员变动触发重分配（期间消费暂停） |
| 事务消息 / 半消息 | RocketMQ 的「先投半消息→执行本地事务→commit/rollback+回查」机制 |
| 死信队列（DLQ） | 消费重试 N 次仍失败后进入的隔离队列，人工兜底 |
| Outbox 模式 | 本地事务里写事件表再异步投递，保证「落库与发消息」的原子性 |
| 倒排索引 | 「词 → 文档列表」的索引结构，全文检索的地基 |
| Canal / XXL-Job | binlog 订阅同步工具 / 分布式调度平台（分片广播、失败重试） |
| Flyway | 数据库迁移工具：表结构变更写成版本化脚本（V1__x.sql），生产禁止手工跑 DDL |
| HikariCP | 数据库连接池：复用连接避免每次建连；关键是最大连接数 / 超时 / 生命周期配置 |

## 微服务与分布式（阶段四）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| CAP / BASE | 分区必然发生时 C 与 A 的取舍 / AP 路线的工程化（最终一致） |
| Raft | 共识算法：Leader 选举 + 多数派日志复制；etcd / KRaft / Nacos CP 的底座 |
| 雪花算法 | 64 位分布式 ID（时间戳+机器+序列）；坑是时钟回拨 |
| 号段模式（Leaf） | DB 批量发号段到本地消耗，压力降一个数量级 |
| Nacos | 注册中心 + 配置中心一体；长轮询动态刷新；AP/CP 可切 |
| Sentinel / Resilience4j | 流控熔断组件（控制台+热点限流）/ 更轻的函数式替代 |
| Seata / AT / TCC | 分布式事务框架 / 自动补偿模式（undo_log）/ 手写三段模式 |
| 全局锁 | Seata AT 防脏写的机制：回滚期间锁住行，拒绝其他全局事务写 |
| 熔断三态 | 关闭 → 打开（快速失败）→ 半开（放探测流量）的状态机 |
| 灰度发布 | 按 Header / 权重把流量渐进切到新版本 |
| DDD 术语族 | 限界上下文（模型边界）/ 聚合根（一致性入口）/ 值对象（不可变按值判等）/ 防腐层（模型隔离转换） |
| 事件风暴 | 从业务事件出发梳理流程、聚类出服务边界的建模工作坊 |
| CQRS / Event Sourcing | 读写模型分离 / 事件序列为唯一事实源（审计强，复杂度高） |
| Strangler Fig | 绞杀者模式：新旧并行、逐块迁移流量，遗留系统渐进改造 |
| Dubbo / Triple | 国内老牌 RPC 框架 / 其兼容 gRPC 的新协议 |
| gRPC / Protobuf | HTTP/2 + 二进制 IDL 的跨语言高性能 RPC |
| 服务网格（Istio） | Sidecar 代理接管服务间流量（mTLS / 重试 / 镜像）；中小团队优先 Gateway+K8s |
| Spring Modulith | 单体内按限界上下文分模块的官方方案——微服务前的务实一步 |
| 本地消息表 | 最终一致的最小可行方案：业务表与消息表同事务落库，再靠 MQ + 定时兜底投递——比 Seata 更轻 |
| Outbox | 本地消息表的工程化别名（见阶段四第 5 讲）：保证「落库与发事件」原子性 |

## 云原生与运维（阶段五）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| 多阶段构建 | Dockerfile 先在构建镜像里编译，再只把产物拷进运行镜像 |
| 层缓存 | 镜像按指令分层缓存；先 COPY 依赖清单再 COPY 源码，改代码不击穿依赖层 |
| Distroless / jlink | 无 shell 的极简基础镜像 / 按需裁剪 JRE 模块 |
| K8s 对象速记 | Pod（运行单元）/ Deployment（副本管理）/ Service（稳定入口）/ Ingress（L7 路由）/ ConfigMap+Secret（配置注入）/ PV+PVC（持久卷） |
| 三种探针 | liveness（挂了重启容器）/ readiness（没就绪摘流量）/ startup（慢启动保护） |
| preStop / 优雅停机 | 摘流量等待 + 等在途请求完成，滚动更新不丢请求的双保险 |
| HPA | 按 CPU / QPS 自动扩缩副本数 |
| Helm | K8s 的包管理 + 模板引擎，values 分环境 |
| GitOps / ArgoCD | 期望状态存 Git，控制器持续收敛集群；漂移检测、回滚 = git revert |
| 漂移（Drift） | 有人手改了集群资源，实际状态偏离 Git 声明 |
| 四大黄金信号 | 延迟 / 流量 / 错误 / 饱和度——服务监控的最小集 |
| RED / USE | 服务视角（Rate/Errors/Duration）/ 资源视角（Utilization/Saturation/Errors） |
| Micrometer | Java 指标门面（Boot 内置），对接 Prometheus |
| OpenTelemetry | 可观测统一规范（指标+日志+追踪），未来事实标准 |
| SkyWalking | 国内主流 APM，Java Agent 字节码增强无侵入埋点 |
| jstack / jmap / jstat | 抓线程栈（定位死锁高 CPU）/ 堆快照（OOM 分析）/ GC 统计 |
| Arthas | 在线诊断工具：watch 观察方法 / trace 耗时链 / dashboard，不重启进程 |
| 火焰图 | 横轴宽度 = 方法占 CPU 比例，一眼看到热点 |

## 架构设计与安全（阶段六）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| SLI / SLO / SLA | 测量什么 / 内部目标 / 对外合同承诺 |
| 脑裂 | 主备切换期间双主同写导致数据撕裂；用 quorum 仲裁防 |
| 异地多活 / 单元化 | 多机房同时服务；流量按用户分片到自包含的「单元」 |
| 混沌工程 | 主动注入故障验证「我们扛得住」的假设 |
| p99 | 99% 请求快于该值的长尾指标；平均值会骗人 |
| Little's Law | 并发数 = QPS × RT；容量估算的第一公式 |
| 全链路压测 | 染色标记压测流量 + 影子表隔离数据 + 挡板隔离第三方 |
| OWASP Top 10 | Web 安全风险清单（注入 / 越权 / 反序列化等） |
| SSRF | 服务端请求伪造：诱导后端去访问内网地址 |
| 反序列化漏洞 | Java 重灾区：恶意字节流触发任意代码执行（Fastjson 历史） |
| 零信任 / mTLS | 不因「在内网」就信任；服务间双向证书认证 |
| 等保 2.0 | 国内信息系统安全等级保护制度（日志留存 / 审计 / 加密的来源） |
| N+1 查询 | 循环里逐条查关联，1 条变 N+1 条；用批量查询 / JOIN / fetchJoin 解 |
| 错误预算 | SLO 允许的失败额度，作为故障止损与发布节奏的量化依据 |
| 多租户 | 一套系统服务多个租户；隔离 = 共享表+tenant_id（逻辑）/ 独立 Schema / 独立库（物理），成本随隔离度递增 |
| 租户上下文 | 请求生命周期里携带 tenant_id 的 ThreadLocal；必须在有线程池时 finally clear，否则串租户 |
| TenantLine 拦截器 | MyBatis-Plus 自动给 SQL 拼 tenant_id 的拦截器——「漏写也不会漏」的强制隔离手段 |

## 数据库专家（阶段八）

| 术语 | 用途（大白话） |
| ---------------- | ----------------------------------------------- |
| 主从复制 | 主库写、从库读/备份；解决读扩展 + 高可用，不解决写扩展 |
| 读写分离 | 写走主、读走从；分担读压力，但有主从延迟 |

| 分片键 | 决定数据在哪个分片/分库的字段；选最高频查询维度 |
