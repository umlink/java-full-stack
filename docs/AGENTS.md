# docs/AGENTS.md

本文件定义 `docs/` 文档维护规则。

## 1. 文档定位

- `docs/` 是学习内容与技术决策的权威来源。
- `docs/10-实战产品蓝图/实践计划/` 是实践卡片和进度状态的权威来源。
- 文档修改必须服务学习闭环：准确、可验证、可追溯。

## 2. 模板

- 阶段零至阶段七保留既有七段式结构：
  - 快速入门。
  - 精简大纲。
  - 学习内容详情。
  - 坑点提醒。
  - 本节自检。
  - 本节配套思考题。
  - 常见面试题。
- 阶段八使用独立模板，不套阶段零至七格式。
- 不删除既有 `⏸️ 短期可以不学` 框、代码块、面试题三层答法、前端对照。

## 3. 写作规则

- 简体中文。
- 术语首次出现必须解释。
- 只出现一次的专业词也必须解释。
- 机制类内容优先用 Mermaid。
- Mermaid 类型按内容选择：流程用 flowchart，时序用 sequenceDiagram，状态用 stateDiagram，类关系用 classDiagram，排期用 gantt。
- Mermaid 节点文本包含半角引号或括号时，用 `["..."]` 包裹或改中文标点。
- 类比必须采用“生活版 → 技术结论”双段式。
- 面向前端背景读者时，优先使用 NestJS、npm、RxJS、浏览器请求链路做对照。

## 4. 内容质量

- 不堆术语。
- 不重复解释同一概念。
- 快速入门只做导航和最低理解门槛。
- 正文负责机制、场景、代价、工程落点。
- 坑点提醒只保留正文未集中解决的风险。
- 面试题不得引入正文没有解释过的新概念。

## 5. 链接与重命名

- 重命名文件或目录必须同步审计交叉链接。
- 修改文档结构后使用 `rg` 检查旧路径、旧标题、旧文件名。
- 实践卡片完成记录必须写明日期、结果和可复现证据。
- 未验证内容不得标记完成。
