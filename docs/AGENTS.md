# docs/AGENTS.md

本文件定义 `docs/` 文档维护规则。

## 1. 文档定位

- `docs/` 是学习内容与技术决策的权威来源。
- [实践计划与进度](10-实战产品蓝图/实践计划/README.md) 是实践**进度状态的唯一权威来源**；卡片文件只写任务定义与完成记录，不写状态行。
- 文档修改必须服务学习闭环：准确、可验证、可追溯。

## 2. 模板

- 阶段零至阶段七保留既有七段式结构：
  - 快速入门。
  - 精简大纲。
  - 学习内容详情。
  - 坑点提醒。
  - 本节自检。
  - 本节配套思考题。
  - 常见面试题。
- 阶段八使用独立模板，不套阶段零至七格式。
- 不删除既有 `⏸️ 短期可以不学` 框、代码块、面试题三层答法、前端对照。

## 3. 写作规则

- 简体中文。
- 术语首次出现必须解释。
- 只出现一次的专业词也必须解释。
- 机制类内容优先用 Mermaid。
- Mermaid 类型按内容选择：流程用 flowchart，时序用 sequenceDiagram，状态用 stateDiagram，类关系用 classDiagram，排期用 gantt。
- Mermaid 节点文本包含半角引号或括号时，用 `["..."]` 包裹或改中文标点。
- 类比必须采用“生活版 → 技术结论”双段式。
- 面向前端背景读者时，优先使用 NestJS、npm、RxJS、浏览器请求链路做对照。

## 4. 内容质量

- 不堆术语。
- 不重复解释同一概念。
- 快速入门只做导航和最低理解门槛。
- 正文负责机制、场景、代价、工程落点。
- 坑点提醒只保留正文未集中解决的风险。
- 面试题不得引入正文没有解释过的新概念。

## 5. 链接与重命名

- 重命名文件或目录必须同步审计交叉链接。
- 修改文档结构后使用 `rg` 检查旧路径、旧标题、旧文件名。
- 实践卡片完成记录必须写明日期、结果和可复现证据。
- 未验证内容不得标记完成。

## 6. 产品实现导航

- [后端实现导航树](/PRODUCT_TREE.md) 是面向学习的代码地图：记录 `boot-server/` 的真实目录、模块职责、已实现功能、关键技术点及对应测试入口。
- 该文档中的 `已实现`、`未实现` 仅表示源码功能是否存在；里程碑、卡片顺序与「待开始 / 进行中 / 已完成」等实践进度始终以 [实践计划与进度](10-实战产品蓝图/实践计划/README.md) 为唯一来源，不在导航树复制维护。
- 新增、删除或调整后端模块、核心技术方案、关键接口、数据模型、安全机制或测试入口时，须同步更新导航树；描述必须能够定位到真实目录或类，不能把计划中的功能写成已经实现。
