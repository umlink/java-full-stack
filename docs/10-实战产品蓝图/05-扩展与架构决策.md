## 横切能力清单

横切能力是每个模块都用、与具体业务无关的能力。它们按当前里程碑逐步补齐，而不是一次性引入所有库。

| 技术点 | 解决什么 | 当前状态 |
|-|-|-|
| 统一响应体 `Result` | 所有接口返回结构一致 | ✅ 已就位 |
| 参数校验 `@Valid` | 入参声明式校验 | M1 第 1 张卡片 |
| 全局异常 `@RestControllerAdvice` | 异常集中转 JSON，不裸抛 500 | M1 第 1 张卡片 |
| MDC TraceId | 一次请求的日志串起来 | 待阶段 2 收口 |
| SpringDoc | 自动生成 OpenAPI 接口契约 | M1 第 6 张卡片 |
| Jackson 脱敏 | 手机号、身份证等字段按需打码 | 有敏感字段后启用 |
| MapStruct | DTO / Entity 编译期转换 | DTO 数量增加后启用 |
| Hutool | 日期、字符串、加解密等工具 | 标准库不足时按需引入 |

## 防过度设计边界

> ⚠️ 原则：**没有信号，就不上。** 技术是为已被观察到的问题服务的，不是学习完成后的陈列品。

| 重型技术 | 启用信号 | 没有信号时的简单方案 |
|-|-|-|
| 微服务拆分 | 多人并行互相阻塞，或出现独立扩缩容需求 | 模块化单体 |
| 分库分表 | 单表千万级，且慢 SQL 优化到头 | 索引 + 缓存 |
| MQ 异步 | 下单链路被非核心操作拖慢，或压测显示需要削峰 | 同步 + 本地事务 |
| 分布式锁 | 多实例下定时任务或缓存重建重复执行 | 单实例不加锁 |
| 多级缓存 | Redis 网络往返已成瓶颈且有命中率数据 | 单层 Redis 缓存 |
| Elasticsearch | LIKE 查询慢且有真实体验问题 | MySQL 索引 + 模糊查询 |
| 秒杀多级削峰 | 压测得到真实 QPS 拐点 | DB 条件更新 |

**简单优先序**：能单体不拆、能单库不分、能同步不异步、能本地不分布式、能一层不叠层。

| 阶段 | 做什么 | 不做什么 |
|-|-|-|
| 阶段 2 | 登录、RBAC、测试门禁、统一响应 | 不上 Redis、MQ |
| 阶段 3 | 缓存、异步、索引优化 | 不拆服务、不分库分表 |
| 阶段 4 | 拆 2-3 个服务体验治理 | 不上微服务全家桶；Seata、服务网格后置 |
| 阶段 6 | 秒杀、限流熔断、压测 | 分库分表、SkyWalking、K8s 后置 |

## ADR：升级前必须留下决策记录

架构决策记录（ADR）是一次技术取舍的短说明。任何表中的重型技术启用、替换或撤回，都在 [adr/README](adr/README.md) 的索引中新增一份记录。

记录至少回答三件事：

> **决策**：哪个阶段引入或移除了什么。
>
> **触发信号与备选**：观察到了什么；对比过哪些替代方案。
>
> **回退成本**：决策错误时如何回到简单方案，需要付出什么代价。

示例：

> **决策**：阶段 3 引入 Redis Lua 预扣 + DB 条件更新。
>
> **触发信号与备选**：压测 500 QPS 下单出现 2% 超卖；对比纯 DB 条件更新与乐观锁后，前者并发不足、后者冲突重试过多。
>
> **回退成本**：删除 Lua 脚本与缓存字段，保留 DB 条件更新，1 天内可回退。
