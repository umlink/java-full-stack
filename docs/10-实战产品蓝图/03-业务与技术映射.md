## 怎么使用映射表

每一行都回答三个问题：**什么业务问题、为什么选它、恰好在哪个阶段学到**。先有问题再找技术，不是学完技术就到处引入。看到「不落地」或「可选」时，不是遗漏，而是刻意保留简单方案。

## 阶段 0-2：工程与安全后台

| 业务场景 / 问题 | 技术方案（为什么是它） | 对应文档 | boot-app 落点 |
|-|-|-|-|
| 工程骨架怎么搭、依赖版本谁管 | Boot 多模块聚合工程：`infrastructure/` 底座 + `services/` 服务，父 pom 用 BOM 锁版本 | 阶段二第 2 讲 | ✅ 已就位 |
| 接口返回结构不统一 | `Result` 统一响应体 + `@RestControllerAdvice` 全局异常 | 阶段零 05 讲 / 阶段二第 3 讲 | `Result` ✅ 已就位；全局异常待补 |
| 用户重复点击 / 网络重试造成重复下单 | 幂等三板斧：token → 唯一索引 → 状态机条件更新，按成本递增选择 | 阶段二第 3 讲 | 幂等注解 + 拦截器 |
| 参数错误散落一堆 if | `@Valid` 与校验注解，声明式校验 | 阶段二第 3 讲 | Controller 请求 DTO |
| 密码明文入库 | BCrypt 单向哈希，不可逆且自动加盐 | 阶段二第 6 讲 | 注册接口改造 |
| 登录态怎么做 | JWT 无状态令牌，适合水平扩展 | 阶段二第 6 讲 | M1 登录接口 |
| 谁有权访问什么接口 | RBAC：用户挂角色、角色挂权限 | 阶段二第 6 讲 | 角色 / 权限表 + 授权规则 |
| 横切逻辑重复 | Filter → Interceptor → AOP 分层拦截 | 阶段二第 1/3 讲 | 认证过滤器与业务切面 |
| 浏览器跨域 | CORS 白名单配置 | 阶段二第 3 讲 | 配置类 |
| 联调没有契约 | SpringDoc OpenAPI 自动生成接口文档 | 阶段二第 3 讲 | M1 依赖与配置 |
| 多环境配置混杂 | `application-{env}.yml` profile | 阶段二第 2 讲 | dev / prod 配置 |
| 注册后非核心操作拖慢主流程 | `@Async` + Spring 事件，先解耦再决定是否上 MQ | 阶段二第 1 讲 | 注册成功事件 |
| 超时订单处理 | 单机先用 `@Scheduled`；多实例后再考虑分布式锁或延时消息 | 阶段二第 2 讲 | 阶段 3 启用 |
| 并发修改互相覆盖 | MyBatis-Plus `@Version` 乐观锁；冲突率高且事务短才考虑悲观锁 | 阶段三第 3 讲 | 实体 version 字段 |
| 回归依赖肉眼 | JUnit5、Mockito、Testcontainers 测试门禁 | 阶段二第 5 讲 | service 测试目录 |
| 一次请求日志串不起来 | MDC TraceId 生成和透传 | 阶段二第 3 讲 | 日志拦截器 |
| 详情页串行聚合过慢 | `CompletableFuture` 并行聚合 + `orTimeout` 超时降级 | 阶段一并发章节 / 阶段七第 1 讲 | 商品详情聚合接口 |
| DTO 样板代码多 | Java `record` 作为不可变 DTO | 阶段零 05 讲 | 入参 / 出参改造 |
| 用户头像上传 | `MultipartFile` 接收 + 本地目录暂存 | 阶段二第 3 讲 | 头像上传接口 |

## 阶段 3：交易、数据与中间件

| 业务场景 / 问题 | 技术方案（为什么是它） | 对应文档 | boot-app 落点 |
|-|-|-|-|
| 零安装跑库 | H2 嵌入式数据库，`MODE=MySQL` 降低后续切换成本 | 阶段二第 5 讲 | ✅ 已就位 |
| H2 不再满足数据或特性要求 | 引入 MySQL profile 与驱动，保持数据源配置隔离 | 阶段三第 1 讲 | 新 profile + 依赖 |
| 连接反复创建销毁 | HikariCP 连接池复用连接；Boot 默认已提供，按压测数据调参 | 阶段三第 1 讲 | 默认即有 |
| 慢查询 | 索引设计 + `EXPLAIN`，先看执行计划再谈分库分表 | 阶段三第 1 讲 | 订单 / 明细索引 |
| 单表千万级且优化到头 | 分库分表；没有信号只写 ADR，不落地 | 阶段三第 2 讲 | 不落地 |
| ORM 样板重复 | MyBatis-Plus 的 Mapper、Service、自动填充和分页 | 阶段三第 3 讲 | 新增业务 Mapper |
| 下单多表写留半截 | `@Transactional` 划定订单、明细、库存的本地事务边界 | 阶段三第 1 讲 | 下单服务 |
| 购物车高频读写 | Redis Hash，例如 `cart:{userId}` | 阶段三第 4 讲 | M2.5 cart 模块 |
| 字典 / 商品列表反复查库 | 先 `@Cacheable`；需要时再引入 Caffeine + Redis 多级缓存 | 阶段三第 4 讲 | 字典缓存 |
| 缓存击穿 | 互斥重建与 Redis 分布式锁 | 阶段三第 4 讲 | 商品详情热点 key |
| 高并发扣库存超卖 | Redis Lua 预扣 → DB 条件更新 → 定时对账 | 阶段三第 4 讲 / 阶段六第 2 讲 | 库存服务 |
| 非核心操作拖慢下单 | RocketMQ 事件异步化 | 阶段三第 5 讲 | 订单事件 |
| 超时未支付订单取消 | RocketMQ 延时消息，自动关单并释放库存 | 阶段三第 5 讲 | 延时 topic |
| 商品搜索体验差 | Elasticsearch 倒排索引；仅在 LIKE 已慢且有体验问题时启用 | 阶段三第 6 讲 | 可选 |
| 跨天对账 | XXL-Job 集群化调度 | 阶段三第 6 讲 | 对账任务 |

## 阶段 4：服务化与治理

| 业务场景 / 问题 | 技术方案（为什么是它） | 对应文档 | boot-app 落点 |
|-|-|-|-|
| 多人协作阻塞或需要独立扩缩容 | user / product / order 服务拆分；没有信号则保持模块化单体 | 阶段四第 1 讲 | `services/` 下加模块 |
| 服务地址难维护 | Nacos 注册与配置中心 | 阶段四第 2 讲 | 新增依赖 |
| 统一鉴权、限流与路由 | Gateway 网关 | 阶段四第 2 讲 | gateway 模块 |
| 服务间调用 | OpenFeign 声明式 HTTP 客户端 | 阶段四第 5 讲 | 服务调用 |
| 订单号唯一且避免泄露量级 | 雪花 ID；与 UUID、号段对比后选择 | 阶段四第 3 讲 | common-core ID 生成器 |
| 跨服务事务 | 首选本地事务 + 消息补偿；Seata 只在有明确需求时评估 | 阶段四第 2/3 讲 | ADR，默认不落地 |
| 洪峰下的限流熔断 | Sentinel 流控与降级 | 阶段四第 2 讲 | 限流规则 |
| 消息与本地事务不一致 | Outbox 发件箱模式 | 阶段四第 3 讲 | order 服务 |
| 接口被重放刷单 | timestamp + nonce + sign 验签 | 阶段四第 5 讲 | 网关过滤器 |
| 业务边界混乱 | DDD 限界上下文，订单域不直接写库存表 | 阶段四第 4 讲 | 包结构重构 |

## 阶段 6：高并发与可用性

| 业务场景 / 问题 | 技术方案（为什么是它） | 对应文档 | boot-app 落点 |
|-|-|-|-|
| 秒杀洪峰 | 前端静态化 → 网关限流 → 预扣库存 → MQ 排队 → 异步落单 → 对账 | 阶段六第 2/3 讲 | 秒杀模块 |
| 热点 SKU 锁竞争 | 库存分段，拆分为 N 个可独立扣减的分桶 | 阶段六第 2 讲 | 库存分桶表 |
| 洪峰限流 | 单机用 Guava RateLimiter；多实例再用 Sentinel 集群限流 | 阶段六第 2 讲 | 网关 / 秒杀接口 |
| 依赖故障扩散 | 熔断三态与可验证的降级预案 | 阶段六第 3 讲 | 订单查询降级 |
| 系统是否扛得住 | k6 压测报告 + SLA 演练，找出拐点和容量水位 | 阶段六第 1/6 讲 | 脚本 + 报告 |
| 安全风险 | OWASP 清单：越权、注入、XSS、CSRF、防脚本 | 阶段六第 5 讲 | 安全加固 |
| 多商家隔离 | 共享库 + 租户 ID，量上来再评估独立库 | 阶段六第 7 讲 | 可选 |
