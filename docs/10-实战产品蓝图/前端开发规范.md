# 前端开发规范

适用于 `admin-client/` 与 `user-client/`。技术栈：React 19、TypeScript、Vite、React Router、Tailwind CSS 4、shadcn/ui、Base UI、Lucide。

## 1. 目录

```text
src/
  App.tsx
  main.tsx
  router.tsx
  api/
    modules/
  assets/
  components/
    ui/
  hooks/
  layouts/
  lib/
  pages/
  providers/
```

- `pages/`：路由页面。
- `layouts/`：跨页面布局。
- `providers/`：全局 Provider。
- `components/`：跨页面组件。
- `components/ui/`：shadcn/ui 组件落点。
- `hooks/`：跨页面 Hook。
- `lib/`：HTTP、鉴权、环境变量、工具函数。
- `api/`：按业务模块封装的接口定义与统一类型出口（详见第 6 节）。
- `assets/`：静态资源。

禁止：

- 禁止新增 `src/app/`。
- 禁止新增 `src/features/`。
- 禁止新增 `components/layout/`。
- 禁止把路由页面平铺为 `users-page.tsx`、`login-page.tsx`。

## 2. 页面

页面固定结构：

```text
pages/
  Users/
    index.tsx
    components/
    useUsersService.ts
```

- 页面目录使用 PascalCase。
- 页面入口固定为 `index.tsx`。
- 页面组件导出名使用 `XxxPage`。
- 页面私有组件放 `pages/<PageName>/components/`。
- 页面私有状态、请求、事件编排放 `useXxxService.ts`。
- 页面私有类型需要独立文件时放 `types.ts`。
- 两个及以上页面复用的组件，才移动到 `src/components/`。

## 3. 命名

- 自有 React 组件文件：PascalCase，例如 `AdminLayout.tsx`。
- 页面目录：PascalCase，例如 `pages/Users/`。
- Hook 文件：`useXxx.ts`。
- 页面 service Hook：`useXxxService.ts`。
- 工具文件：lowerCamelCase，例如 `request.ts`、`authSession.ts`。
- 类型文件：`types.ts`。
- 路由入口：`router.tsx`。
- CSS 入口：`index.css`。
- shadcn/ui 文件保持小写，不手工改名。

导出命名：

- 组件：`Xxx`。
- 页面：`XxxPage`。
- Hook：`useXxx`。
- Props：`XxxProps`。
- 请求类型：`XxxRequest`。
- 响应类型：`XxxResponse`。
- 路由守卫：`XxxRoute`。

## 4. 路由

- 路由统一写在 `src/router.tsx`。
- 页面 import 使用目录入口：`@/pages/Users`。
- 布局 import 使用文件入口：`@/layouts/AdminLayout`。
- 应用内跳转使用 React Router。
- 禁止用 `window.location` 做应用内跳转。
- 受保护页面必须显式包裹路由守卫。
- 404 页面必须集中配置。

## 5. 组件

- shadcn/ui 已有语义组件时必须优先使用。
- 禁止手写重复的按钮、输入框、卡片、弹窗、侧栏基础组件。
- 页面组件负责组合，不直接处理底层请求细节。
- 展示组件不发请求、不读写 token。
- 组件 props 必须有明确类型。
- 禁止使用 `any`。
- 复杂 JSX 先拆页面私有组件。

## 6. HTTP

- 服务端基础地址只从 `VITE_API_BASE_URL` 读取。
- 环境变量读取封装在 `lib/`。
- 页面禁止硬编码主机、端口、`/api` 前缀。
- 统一 `request` 客户端处理 JSON、`Result<T>`、HTTP 错误、网络错误、Authorization。
- 接口定义按业务模块放 `api/modules/<module>.ts`（如 `login.ts`），模块类型放同目录 `type.d.ts`；统一类型出口 `api/API.d.ts` re-export 各模块类型，页面只从 `@/api/API` 引类型、从 `@/api/modules/<module>` 调接口，不深入拼路径。
- 页面和 service Hook 禁止重复解析 `code`、`message`、`data`。
- `401/40100`：清 token，跳登录。
- `403/40300`：保留会话，显示无权限。

统一响应：

```ts
type Result<T> = {
  code: number
  message: string
  data: T
}
```

## 7. 认证

- JWT 只存 `sessionStorage`。
- token 读写必须封装。
- token 禁止进入 URL、日志、错误提示、localStorage、React 状态快照。
- 路由守卫只判断登录状态。
- 权限最终以后端 `401`、`403` 为准。
- 登出必须清 token 和用户缓存。

## 8. 状态

- 异步页面必须处理加载、成功、空数据、失败。
- 受保护页面必须处理未登录、无权限。
- 页面 service Hook 负责页面私有状态编排。
- 跨页面状态必须进入明确的 Provider、Hook 或 `lib/` 模块。
- 禁止在多个页面复制同一套请求状态处理。

推荐状态：

```ts
type PageState = "loading" | "ready" | "empty" | "error" | "forbidden"
```

## 9. UI

- 后台页面优先紧凑、稳定、可扫描。
- 必须覆盖加载、空、错误、无权限状态。
- Tailwind 只做布局和局部样式。
- 图标使用 Lucide。
- 图标按钮必须有 `aria-label`。
- 表单字段必须有 `Label`。
- 禁止卡片嵌套卡片。
- 禁止营销式 hero 和装饰性大卡片用于后台页面。
- 文本不得溢出按钮、表格、侧栏和卡片。

## 10. 静态值治理

- 只有可部署配置、共享存储、权限/错误码、跨层机器协议，以及确有多个消费者且独立演进的全局策略/阈值需要唯一命名来源；重复出现本身不是抽常量理由。
- 路由表、`Link`、`Navigate`、`navigate` 和请求错误跳转的路径属于局部声明，可直接写为 `"/login"`、`"/users"`；路径在多处出现本身不构成抽常量的理由，不建立 `routes.ts` 或巨型路径常量表。单一接口模块专用的 endpoint 同样可直接写为 `request("/auth/login")`、`request("/users")`；即使有多个调用方，endpoint 仍由所属 API 模块就近声明，调用方不得自行拼接。环境变量键只在 `lib/env.ts`；存储键只在所属会话或 Provider 模块；后端错误码只在 `lib/` 契约模块。协议头、MIME 类型、Bearer 方案与 HTTP 状态阈值是统一请求层的显然字面量，就地书写、不抽常量。
- 页面私有的分页默认值、状态码映射、日期格式等可留在 `index.tsx` 或 `useXxxService.ts`；确有同页多文件复用时才放 `pages/<PageName>/config.ts`。跨页面仅在确有多个消费者且需要独立演进时才提升至 `lib/`。禁止建立没有明确所有者的巨型 `constants.ts`。
- 常量名表达语义与所属边界，例如 `API_RESULT_CODE.FORBIDDEN`、`API_RESULT_CODE.UNAUTHORIZED`；不得用 `DEFAULT_VALUE`、`CONFIG_1` 等无领域含义名称。
- 可以保留字面量的边界：路由表与单点导航路径、单一接口模块专用 endpoint、页面/组件表单校验的边界数值/正则/提示语、单个 JSX 节点的展示文案、单组件一次性占位/骨架数量、Tailwind class、单次局部计算、单测 fixture/request/assertion 和框架 API 必需的标签名。它们即使出现多处，也应先按局部声明处理；只有可部署配置、共享存储、跨层机器协议或确有多个消费者且独立演进的策略/阈值才提升为具名定义。
- `components/ui/` 是 shadcn 生成代码，升级前不做机械常量化；自有业务代码仍必须满足本节。

提交前至少扫描自有代码并逐项判断命中是否为允许边界，扫描不是机械替换工具：

```bash
rg -n --glob '*.{ts,tsx}' --glob '!**/components/ui/**' '(/api|/auth|/users|/login|VITE_|sessionStorage|localStorage|\\b[0-9]{3,5}\\b)' src
rg -n --glob '*.{ts,tsx}' --glob '!**/components/ui/**' 'import\.meta\.env|window\.location|fetch\(' src
```

## 11. TypeScript

- 必须遵守 `strict`。
- 禁止 `any`。
- 未知数据用 `unknown` 并收窄。
- 禁止用非空断言掩盖业务空值。
- 有限状态使用联合类型。
- DTO 类型必须对齐后端契约。

## 12. 验证

前端变更必须执行：

```bash
pnpm typecheck
pnpm lint
pnpm build
git diff --check
```

涉及路由、登录、权限、布局时，还必须浏览器验证：

- 首页跳转。
- 登录页访问。
- 受保护页面刷新。
- 401 跳登录。
- 403 显示无权限。
- 移动端不重叠、不溢出（仅 C 端商城；B 端管理后台面向桌面，见 `admin-client/AGENTS.md`）。

## 13. 提交检查

- 没有新增禁止目录。
- 页面符合 `pages/<PageName>/index.tsx`。
- 自有组件文件使用 PascalCase。
- Hook 文件使用 `useXxx.ts`。
- 页面 service Hook 使用 `useXxxService.ts`。
- 页面没有硬编码 API 地址。
- 页面没有直接读写 token。
- 环境键、存储键、错误码和跨层机器协议有明确所有者；路由表、导航目标、单一接口模块 endpoint 及页面局部校验/展示规则保留就近字面量，已执行静态值扫描并审查命中项。
- 页面状态分支完整。
- shadcn/ui 可表达的控件没有被手写替代。
- 验证命令全部通过。
