# 前端开发规范

适用于 `admin-client/` 与 `user-client/`。技术栈：React 19、TypeScript、Vite、React Router、Tailwind CSS 4、shadcn/ui、Base UI、Lucide。

## 1. 目录

```text
src/
  App.tsx
  main.tsx
  router.tsx
  assets/
  components/
    ui/
  hooks/
  layouts/
  lib/
  pages/
  providers/
```

- `pages/`：路由页面。
- `layouts/`：跨页面布局。
- `providers/`：全局 Provider。
- `components/`：跨页面组件。
- `components/ui/`：shadcn/ui 组件落点。
- `hooks/`：跨页面 Hook。
- `lib/`：HTTP、鉴权、环境变量、工具函数。
- `assets/`：静态资源。

禁止：

- 禁止新增 `src/app/`。
- 禁止新增 `src/features/`。
- 禁止新增 `components/layout/`。
- 禁止把路由页面平铺为 `users-page.tsx`、`login-page.tsx`。

## 2. 页面

页面固定结构：

```text
pages/
  Users/
    index.tsx
    components/
    useUsersService.ts
```

- 页面目录使用 PascalCase。
- 页面入口固定为 `index.tsx`。
- 页面组件导出名使用 `XxxPage`。
- 页面私有组件放 `pages/<PageName>/components/`。
- 页面私有状态、请求、事件编排放 `useXxxService.ts`。
- 页面私有类型需要独立文件时放 `types.ts`。
- 两个及以上页面复用的组件，才移动到 `src/components/`。

## 3. 命名

- 自有 React 组件文件：PascalCase，例如 `AdminLayout.tsx`。
- 页面目录：PascalCase，例如 `pages/Users/`。
- Hook 文件：`useXxx.ts`。
- 页面 service Hook：`useXxxService.ts`。
- 工具文件：lowerCamelCase，例如 `request.ts`、`authSession.ts`。
- 类型文件：`types.ts`。
- 路由入口：`router.tsx`。
- CSS 入口：`index.css`。
- shadcn/ui 文件保持小写，不手工改名。

导出命名：

- 组件：`Xxx`。
- 页面：`XxxPage`。
- Hook：`useXxx`。
- Props：`XxxProps`。
- 请求类型：`XxxRequest`。
- 响应类型：`XxxResponse`。
- 路由守卫：`XxxRoute`。

## 4. 路由

- 路由统一写在 `src/router.tsx`。
- 页面 import 使用目录入口：`@/pages/Users`。
- 布局 import 使用文件入口：`@/layouts/AdminLayout`。
- 应用内跳转使用 React Router。
- 禁止用 `window.location` 做应用内跳转。
- 受保护页面必须显式包裹路由守卫。
- 404 页面必须集中配置。

## 5. 组件

- shadcn/ui 已有语义组件时必须优先使用。
- 禁止手写重复的按钮、输入框、卡片、弹窗、侧栏基础组件。
- 页面组件负责组合，不直接处理底层请求细节。
- 展示组件不发请求、不读写 token。
- 组件 props 必须有明确类型。
- 禁止使用 `any`。
- 复杂 JSX 先拆页面私有组件。

## 6. HTTP

- 服务端基础地址只从 `VITE_API_BASE_URL` 读取。
- 环境变量读取封装在 `lib/`。
- 页面禁止硬编码主机、端口、`/api` 前缀。
- 统一 `request` 客户端处理 JSON、`Result<T>`、HTTP 错误、网络错误、Authorization。
- 页面和 service Hook 禁止重复解析 `code`、`message`、`data`。
- `401/40100`：清 token，跳登录。
- `403/40300`：保留会话，显示无权限。

统一响应：

```ts
type Result<T> = {
  code: number
  message: string
  data: T
}
```

## 7. 认证

- JWT 只存 `sessionStorage`。
- token 读写必须封装。
- token 禁止进入 URL、日志、错误提示、localStorage、React 状态快照。
- 路由守卫只判断登录状态。
- 权限最终以后端 `401`、`403` 为准。
- 登出必须清 token 和用户缓存。

## 8. 状态

- 异步页面必须处理加载、成功、空数据、失败。
- 受保护页面必须处理未登录、无权限。
- 页面 service Hook 负责页面私有状态编排。
- 跨页面状态必须进入明确的 Provider、Hook 或 `lib/` 模块。
- 禁止在多个页面复制同一套请求状态处理。

推荐状态：

```ts
type PageState = "loading" | "ready" | "empty" | "error" | "forbidden"
```

## 9. UI

- 后台页面优先紧凑、稳定、可扫描。
- 必须覆盖加载、空、错误、无权限状态。
- Tailwind 只做布局和局部样式。
- 图标使用 Lucide。
- 图标按钮必须有 `aria-label`。
- 表单字段必须有 `Label`。
- 禁止卡片嵌套卡片。
- 禁止营销式 hero 和装饰性大卡片用于后台页面。
- 文本不得溢出按钮、表格、侧栏和卡片。

## 10. TypeScript

- 必须遵守 `strict`。
- 禁止 `any`。
- 未知数据用 `unknown` 并收窄。
- 禁止用非空断言掩盖业务空值。
- 有限状态使用联合类型。
- DTO 类型必须对齐后端契约。

## 11. 验证

前端变更必须执行：

```bash
pnpm typecheck
pnpm lint
pnpm build
git diff --check
```

涉及路由、登录、权限、布局时，还必须浏览器验证：

- 首页跳转。
- 登录页访问。
- 受保护页面刷新。
- 401 跳登录。
- 403 显示无权限。
- 移动端不重叠、不溢出。

## 12. 提交检查

- 没有新增禁止目录。
- 页面符合 `pages/<PageName>/index.tsx`。
- 自有组件文件使用 PascalCase。
- Hook 文件使用 `useXxx.ts`。
- 页面 service Hook 使用 `useXxxService.ts`。
- 页面没有硬编码 API 地址。
- 页面没有直接读写 token。
- 页面状态分支完整。
- shadcn/ui 可表达的控件没有被手写替代。
- 验证命令全部通过。
