# M2.5-01：Redis 购物车

返回 [实践计划与进度](../README.md)。

## 目标

把购物车条目的高频读写迁入 Redis Hash，并保持用户隔离、数量边界和现价查询契约。

## 范围

- 以用户为边界使用 `bootmall:cart:{userId}` Hash；field 为 SKU id，value 只保存条目 id 与数量，不复制商品名或价格。
- Redis 模式默认启用；加购、改数量、删除与列表走 Redis 适配器，30 天滑动 TTL 由配置源提供。
- 原子脚本保证并发首次加购、重复累加和 999 上限；条目 id 继续作为更新、删除的外部定位符。
- 旧数据库条目在用户首次访问时惰性迁移：先幂等写 Redis、再写迁移标记、最后删除该用户旧行；迁移锁避免同一用户并发搬运。
- Redis 模式故障时返回统一系统错误，不按请求回退数据库；数据库适配器只作为显式回退模式，避免双写分叉。
- 记录操作、迁移、冲突和故障指标，并让 Redis 参与健康检查。
- 通过 `catalog.api` 批量补齐商品现价，不把价格作为购物车事实。

## 契约与最小场景

- HTTP 方法、路径、鉴权、请求响应 JSON 和既有错误码不变。
- 同一用户同一 SKU 只有一个 Hash field；不同用户使用不同 key。
- 首次并发加购只有一个条目，所有成功增量精确累加；结果超过 999 时拒绝且原值不变。
- Redis 故障不读取或写入 `t_cart_item`；恢复 Redis 后继续使用原 key。
- 显式设置 `BOOT_REDIS_CART_ENABLED=false` 可切回数据库适配器，但已经迁移的新购物车属于 Redis，回退前需按运维步骤导出或接受清空瞬态购物车。

## 学习点

Redis Hash、聚合数据所有权、原子字段更新、过期策略与数据迁移。

## 验收

1. 同一用户的购物车读写正确，不同用户互不可见。
2. 重复加购和并发改数量仍满足既有数量不变式。
3. Redis 故障行为、指标和恢复步骤有自动化与真实服务证据。
4. 旧数据库条目首次访问后保留原条目 id 与数量进入 Redis，旧行被清理，重复迁移不复活旧数据。
5. 受影响服务测试和全量回归通过。

## 验证命令

按开卡时锁定的 Redis 运行配置执行真实服务集成测试，再运行 `mvnw.cmd -pl services/user-service -am clean test` 与 `git diff --check`。

## 不做

- 不做库存预扣、订单异步化或前端页面。
- 不把商品价格复制为购物车权威数据。
- 不做 Redis 与数据库长期双写，不在 Redis 故障时静默降级到旧表。

测试与实现证据：

- `cart` 模块新增 Redis Hash 存储适配器：`bootmall:cart:{userId}` 以 SKU id 为 field，只保存条目 id 与数量；加购、改量和删除由 Redis 3.0.504 可执行的 Lua 脚本完成，首次并发加购最终只有一个 field，数量上限仍由 `CartQuantity.MAX=999` 守护。
- Redis 模式默认启用并采用 30 天滑动 TTL；数据库适配器只在 `BOOT_REDIS_CART_ENABLED=false` 时装配。数据库模式保留每步独立事务，Redis 模式不持有数据库事务等待网络调用，原有 HTTP 路径、鉴权、响应 JSON、错误码与商品现价查询契约未变。
- 旧 `t_cart_item` 条目在用户首次访问时通过短租约锁迁移，保留原条目 id 和数量；迁移按 Redis 数据、待清理标记、数据库独立事务删除、完成标记的顺序执行，失败后可从待清理状态重试，完成后不再读取旧表。
- Redis 故障真实 HTTP 测试连接不可用端口，购物车返回 `500/50000`，旧数据库条目未被读取、修改或删除；正常操作、迁移、冲突、溢出和故障通过 `bootmall.cart.redis.operations` 的有限标签记录，Redis 默认参与 Actuator 健康检查。
- 本机 Redis 3.0.504 仅监听 `127.0.0.1:6389` 且关闭持久化，真实服务测试覆盖旧行迁移、重复访问不复活、四路并发加购精确得到 14、跨用户隔离、改量/删除、999 溢出、TTL、指标和健康检查；测试结束后已关闭该进程。
- JDK 25.0.4.1 下以真实 Redis 执行 `boot-server/mvnw.cmd -pl services/user-service -am clean test`：35 份 Surefire 报告共 146 个测试，失败、错误、跳过均为 0；`git diff --check` 通过。
- 静态值审计确认：Redis 主机、端口、超时、购物车开关、TTL、迁移锁和等待时长均从 Spring 配置源读取；稳定 key、迁移状态与指标名由 `RedisCartItemRepository` 集中持有；HTTP 路由、Mapper SQL、Lua 参数、测试端口和断言数据按职责就近保留；本卡未改变 MVC 前缀、业务错误码、权限码或数据库结构。
