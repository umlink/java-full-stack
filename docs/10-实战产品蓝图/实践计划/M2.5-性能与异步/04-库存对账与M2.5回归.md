# M2.5-04：库存对账与 M2.5 回归

返回 [实践计划与进度](../README.md)。

## 目标

定时发现并修复 Redis 预扣库存与数据库事实的差异，完成 M2.5 的缓存、幂等消费和超时关单全量验收。

## 范围

- 数据库 `total_count - locked_count` 是可售库存权威值；按 SKU 主键升序游标和配置批次定时扫描有界集合，对比 Redis `_available` 副本，Redis key 缺失视为可惰性重建而不是差异。
- Redis 值与数据库事实不一致或损坏时，以原子 Lua 删除整个 SKU Hash；下一次预占从数据库最新事实重建。删除与并发预占竞争时数据库条件更新仍是最终防线，禁止对 Redis 做非原子的先查后改。
- 对账开关、周期和批次上限从配置源读取；记录一致、缺失、修复、失败计数，差异日志包含 SKU、数据库值和 Redis 值，失败日志保留原因。
- 同一差异重复执行可收敛；单个 SKU 对账失败不得阻断同批其他 SKU，失败项在游标下一轮回绕后重试。
- 故障注入制造 Redis/数据库差异并验证修复。
- 回归 M2 交易闭环与 M2.5 全部 DoD，更新实现导航和完成记录。

## 契约与最小场景

- 输入是上次扫描游标和受配置校验的批次大小；输出包含下一游标、检查数以及一致、缺失、修复、失败数量，扫描不足一批时游标回到起点。
- 人工篡改 Redis 可售量后，一次对账删除差异 key，后续预占按数据库可售量重建；再次对账不重复修复正确数据。
- Redis 对账命令失败时数据库不变、任务继续扫描并产生失败指标；关闭 Redis 或对账开关后不装配定时任务。

## 学习点

对账、可重入修复、定时任务边界、差异指标与故障演练。

## 验收

1. 人工制造的库存差异能被发现并收敛，重复对账不继续改变正确数据。
2. 缓存命中与失效、消息重复消费、超时关单释放库存均有可复现证据。
3. M2 与 M2.5 全量自动化测试通过，真实 Redis 和 RocketMQ 验证完成。
4. 进度、卡片完成记录和实现导航与真实代码一致。
