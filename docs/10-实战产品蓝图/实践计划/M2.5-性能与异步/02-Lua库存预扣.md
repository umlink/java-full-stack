# M2.5-02：Lua 库存预扣

返回 [实践计划与进度](../README.md)。

## 目标

用 Redis Lua 原子校验并预扣可售库存，同时由数据库条件更新继续守住最终库存不变量。

## 范围

- 每个 SKU 使用 `bootmall:inventory:stock:{skuId}` Hash，保存可用量副本与按稳定预占 ID 隔离的预占状态；默认 7 天 TTL 由配置源提供。
- 用户与下单幂等键生成稳定预占 ID；Lua 一次完成初始化、数量校验、可用量扣减和同键尝试计数，相同请求只扣一次，不同内容冲突。
- Redis 预占成功后，订单本地事务仍用数据库条件更新增加 `locked_count`；数据库约束与受影响行数是最终守护者。
- 数据库事务失败时按尝试计数回补 Redis；事务成功后把预占标为已确认。支付实扣不改变 Redis 可用量，取消释放在数据库提交后回补 Redis。
- Redis 不可用或脚本执行异常时记录指标并显式降级为数据库条件更新；不让性能副本故障阻断原交易链路。
- 设置库存成功后删除 Redis SKU 副本，下次预占从数据库最新可用量重新初始化。
- 记录预占、确认、补偿、释放、失效和降级指标，并增加真实 Redis 并发超卖、同键重复和故障注入验证。

## 契约与最小场景

- HTTP 方法、路径、鉴权、请求响应 JSON 和既有错误码不变；库存不足仍返回 `409/40900`。
- 40 个不同订单并发抢 20 件库存时只允许 20 个成功，Redis 可用量与数据库 `locked_count` 最终分别为 0 和 20。
- 两个相同幂等键、相同内容的并发请求共享一次 Redis 扣减并返回同一订单；相同键不同数量只有一个语义获胜。
- Redis 先成功而数据库后续失败时，订单和数据库锁定量回滚，Redis 预占按尝试计数补偿；补偿调用可重复。
- Redis 完全不可用时订单仍由数据库条件更新决定成功或库存不足，响应不暴露基础设施异常。
- Redis 与数据库发生不可立即修复的差异时记录有限标签指标；M2.5-04 的对账任务负责发现并收敛。

## 学习点

Lua 原子性、库存双层防线、幂等、补偿与故障注入。

## 验收

1. 并发预扣不超卖，数据库库存约束仍是最终守护者。
2. 重复请求不重复预扣；数据库失败时 Redis 预扣能补偿或被对账发现。
3. Redis 不可用时按卡片锁定的降级策略返回稳定业务结果。
4. 真实 Redis 并发测试与全量回归通过。

## 验证命令

按开卡时锁定的并发数运行真实 Redis 测试，再运行 `mvnw.cmd -pl services/user-service -am clean test` 与 `git diff --check`。

## 不做

- 不引入 RocketMQ，不实现超时关单。
- 不移除数据库条件更新或改变订单 HTTP 契约。
- 不把 Redis 库存当作交易事实，不用分布式事务或跨资源锁替代补偿与对账。

测试与实现证据：

- `inventory` 模块新增可关闭的 Redis 预占端口与适配器；`bootmall:inventory:stock:{skuId}` Hash 保存可用量和按稳定 SHA-256 预占 ID 隔离的状态，Lua 原子完成初始化、库存校验、扣减、同键尝试计数、确认、补偿、结算和释放，key 使用可配置的 7 天 TTL。
- 下单在数据库事务前预占 Redis，订单、明细和 `t_stock.locked_count` 仍在同一本地事务中提交，数据库条件更新继续作为最终库存防线；事务失败按尝试计数幂等回补，事务成功标记 `RESERVED`，支付提交后标记 `SETTLED`，取消提交后回补并标记 `RELEASED`。
- Redis 连接或脚本失败记录有限标签指标并返回数据库降级路径；管理员设置库存成功后删除 Redis 副本。关闭 `BOOT_REDIS_INVENTORY_ENABLED` 可恢复仅数据库条件更新，不改变 HTTP 方法、路径、鉴权、响应 JSON 或错误码。
- 订单预占 ID 的机器协议由 `OrderReservationIds` 集中持有；新订单按用户与幂等键生成，缺少幂等键的旧订单按用户与订单 ID 生成兼容标识，支付旧订单的集成测试通过。
- 本机 Redis 3.0.504 仅监听 `127.0.0.1:6389` 且关闭持久化，真实服务测试覆盖 40 个订单抢 20 件只成功 20 个、同键并发只生成一个订单并只扣一次、数据库拒绝后的重复补偿、支付/取消提交后同步、TTL、设置库存失效、指标和 Redis 完全不可用时数据库降级；测试结束后已关闭该进程。
- JDK 25.0.4.1 下以真实 Redis 执行 `boot-server/mvnw.cmd -pl services/user-service -am clean test`：37 份 Surefire 报告共 152 个测试，失败、错误、跳过均为 0；`git diff --check` 通过。
