# 实践计划与进度

返回 [蓝图总览](../README.md)。

这里是执行层的**唯一事实来源**：每张卡片对应一个小而完整的行为、一次独立验证和一次提交；每个里程碑的目标、边界、卡片状态与前置也都记录在本文件。产品范围、领域模型和技术取舍仍分别维护在上层蓝图文档中。

## 进度只在本文件维护

- 卡片文件（`M1-*/0X-*.md`）只写任务定义与完成后的证据档案，**不声明状态**。
- 各工程 `README.md` / `AGENTS.md` **不复述进度**，只指向本文件。

这样「当前进行到哪」只有一个可写位置，不会出现副本互相漂移。

## 使用规则

1. 只开始状态为「待开始」且前置已完成的第一张卡片。
2. 一张卡片只解决一个用户可感知的问题，建议 0.5-2 天内完成。
3. 每张卡片必须先写或补测试，再实现，再用接口验证。
4. 完成后**只改两处**：本文件的卡片状态，以及卡片自己的「完成记录」段；不要悄悄移动到下一张。
5. M2 及以后在前一里程碑 DoD 通过前保持未解锁，不提前拆成实现任务；前置 DoD 通过后，先拆分下一里程碑的卡片，再开始编码。

## 前后端开发顺序

**后端优先；前端不在后端阶段中穿插开发，等大阶段（里程碑）完成后集中接入。**

- 后端 `boot-server/` 是主线，按里程碑（M1 → M2 → M2.5 → M3 → M4）逐卡推进。
- 前端（`admin-client/`、`user-client/`）不跟随单张后端卡片走：等一个里程碑的**后端 DoD 全部通过后**，再为该端建立接入里程碑，按小卡片集中完成（M1-C 即此模式）。
- 原因：后端契约未定稿时写前端，会随契约反复返工；集中到阶段末尾接入，契约已经稳定，前端卡片能一次做扎实。

## 状态约定

| 状态 | 含义 |
|-|-|
| 待开始 | 前置已满足，可以开始 |
| 进行中 | 正在实现，未达到 DoD |
| 已完成 | 测试与接口验证均已记录 |
| 待规划 | 前置里程碑已完成，等待按单卡规则拆分任务 |
| 阻塞 | 有明确外部阻碍，需写明原因 |
| 未解锁 | 前一里程碑尚未完成 |

## M1-C 管理后台接入

**完成定义**：将已完成的 M1 后端认证与用户管理契约接入 `admin-client/`。完成时：管理员可登录并查看用户列表；未登录访问管理页会回到登录页；普通用户访问用户列表会看到 403 无权限状态；前端构建、类型检查和 lint 均通过。

**前置与边界**：

- 后端 M1 已完成，接口文档位于 `http://localhost:8080/api/swagger-ui/index.html`。
- 前端目录、命名、路由、请求、状态和验证统一遵循 [前端开发规范](../前端开发规范.md)。
- 当前注册用户默认是 `USER`；用户列表验收前必须准备一个本地 `ADMIN` 测试账号，不能把临时数据库操作藏在前端代码里。
- 本里程碑只接入认证和用户列表，不做注册页、角色管理、用户编辑、商品、订单或 C 端商城页面。
- `user-client/` 继续保持未拆分状态。按上方「前后端开发顺序」，待 M2 交易核心的后端 DoD 通过后，再建立 C 端接入里程碑和小卡片；不以 Mock 数据替代尚未存在的交易契约。

## 新里程碑的拆分规则

前一里程碑完成后，再为下一里程碑创建目录和卡片。每张卡片至少写清：目标、范围、学习点、验收、验证命令、完成记录和明确的不做项。不要在计划阶段创建未来表、依赖或空模块。
