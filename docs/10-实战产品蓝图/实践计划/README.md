# 实践计划与进度

返回 [蓝图总览](../README.md)。

这里是执行层的唯一事实来源：每张卡片对应一个小而完整的行为、一次独立验证和一次提交。产品范围、领域模型和技术取舍仍分别维护在上层蓝图文档中。

## 使用规则

1. 只开始状态为「待开始」且前置已完成的第一张卡片。
2. 一张卡片只解决一个用户可感知的问题，建议 0.5-2 天内完成。
3. 每张卡片必须先写或补测试，再实现，再用接口验证。
4. 完成后更新卡片中的「完成记录」与本页状态；不要悄悄移动到下一张。
5. M2 及以后在前一里程碑 DoD 通过前保持未解锁，不提前拆成实现任务；前置 DoD 通过后，先拆分下一里程碑的卡片，再开始编码。

## 状态约定

| 状态 | 含义 |
|-|-|
| 待开始 | 前置已满足，可以开始 |
| 进行中 | 正在实现，未达到 DoD |
| 已完成 | 测试与接口验证均已记录 |
| 待规划 | 前置里程碑已完成，等待按单卡规则拆分任务 |
| 阻塞 | 有明确外部阻碍，需写明原因 |
| 未解锁 | 前一里程碑尚未完成 |

## 新里程碑的拆分规则

前一里程碑完成后，再为下一里程碑创建目录和卡片。每张卡片至少写清：目标、前置、范围、学习点、验收、验证命令、完成记录和明确的不做项。不要在计划阶段创建未来表、依赖或空模块。
