# M1-M-00：失效用户 JWT 拦截

返回 [实践计划与进度](../README.md)。

## 目标

让已签发但尚未过期的 JWT 在主体被停用或逻辑删除后立即失去认证资格；受保护接口统一返回 `401/40100`，不泄露账号状态或权限细节。

## 范围

- JWT 验签、过期检查通过后，在写入 `SecurityContext` 前确认主体仍存在、`deleted = 0` 且 `status = 1`。
- 用户有效时再加载当前角色与权限；无权限的有效用户仍是「已认证」主体，不能因权限列表为空被误判为无效用户。
- 用户不存在、已逻辑删除或已停用时，不写入 `SecurityContext`，由既有认证入口统一输出 `401/40100`；响应不区分具体失效原因。
- 调整权限查询或新增专用主体状态查询时，使用参数绑定、显式列名和明确的状态条件；不得只依赖权限关联表是否有记录判断用户是否有效。
- 补真实 HTTP 集成测试：用户登录取得 token 后被停用或逻辑删除，使用旧 token 分别访问 `GET /api/users/me` 与 `GET /api/users`，均得到 HTTP 401 和 `code:40100`。

## 学习点

JWT 的签名有效不等于主体仍有效；认证（主体是否可建立身份）先于授权（主体是否拥有访问权限）。`SecurityContext` 只有在两者的认证前置满足时才可写入。

## 验收

1. 正常 USER token 仍可访问 `GET /api/users/me`，访问 `GET /api/users` 仍返回 403/40300。
2. 正常 ADMIN token 仍可访问 `GET /api/users`。
3. 已登录用户被停用后，其旧 token 访问 `/api/users/me` 与 `/api/users` 均返回 401/40100。
4. 已登录用户被逻辑删除后，其旧 token 访问 `/api/users/me` 与 `/api/users` 均返回 401/40100。
5. `mvnw.cmd -pl services/user-service -am clean test` 在 JDK 25 下通过；记录实际 JDK 版本与测试数量。

## 不做

- 不引入 JWT 黑名单、刷新 token、OAuth2、Redis 或全局强制下线机制。
- 不修改角色管理模型、前端路由或 M2 的表结构。
- 不以缩短 token 有效期替代主体状态检查。
