# M1-02：参数校验

返回 [实践计划与进度](../README.md)。

## 目标

让创建用户的非法输入在进入业务层前被拒绝，并复用 M1-00 已建立的统一错误响应。参数错误使用业务码 `40000`，与资源不存在的 `40400` 区分。

## 范围

- 为 `CreateUserRequest` 增加姓名非空、邮箱格式、年龄范围等校验规则。
- 在 Controller 使用 `@Valid`。
- 验证 M1-00 的全局异常处理器能处理 `MethodArgumentNotValidException`。
- 为合法和非法请求补测试。

## 学习点

Bean Validation、`@Valid`、`MethodArgumentNotValidException` 与 HTTP 400 的职责。

## 验收

1. 非法邮箱、空姓名、越界年龄均不会进入 Service。
2. 响应 HTTP 状态为 400，响应体仍是 `Result`，业务码为 40000。
3. 错误信息能指出第一个非法字段。

## 不做

不处理资源不存在和未知异常；不校验更新接口；不修改 M1-00 的错误码体系。

## 验证

```bash
curl -i -X POST http://localhost:8080/api/users \
  -H "Content-Type: application/json" \
  -d '{"name":"","email":"not-an-email","age":-1}'
```
