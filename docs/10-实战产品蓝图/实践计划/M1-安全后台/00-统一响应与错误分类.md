# M1-00：统一响应与错误分类

状态：**待开始**

返回 [M1 任务列表](README.md)。

## 目标

在新增任何业务接口前，先确定所有成功与失败响应的共同契约。现有 `Result` 继续作为唯一响应包装；新增稳定的错误分类、业务异常基类和全局异常处理器，避免后续 Controller 到处手写错误响应。

## 错误码契约

HTTP 状态码描述通信结果，`Result.code` 描述业务分类。客户端应优先按业务码处理展示和交互，不依赖英文异常文本。

| 分类 | HTTP 状态 | 业务码 | 使用场景 |
|-|-|-|-|
| 成功 | 2xx | `0` | 请求被正常处理 |
| 参数错误 | 400 | `40000` | 请求字段不合法、格式错误 |
| 未认证 | 401 | `40100` | 缺少、失效或篡改的登录凭据 |
| 无权限 | 403 | `40300` | 已登录但没有所需角色或权限 |
| 资源不存在 | 404 | `40400` | 用户、商品、订单等不存在 |
| 业务冲突 | 409 | `40900` | 重复注册、非法状态迁移、库存不足等规则冲突 |
| 系统错误 | 500 | `50000` | 未预期异常；响应不泄露堆栈或内部实现 |

## 范围

- 在 `common-core` 定义错误码枚举或等价的集中定义。
- 定义携带错误分类的业务异常基类。
- 新增 `@RestControllerAdvice`，统一转换业务异常、校验异常和未知异常。
- 保持 `Result` 的成功响应行为不变。
- 未知异常在服务端记录完整日志，对客户端只返回通用信息。

## 学习点

HTTP 状态码与业务错误码的职责、异常作为跨层控制流、`@RestControllerAdvice`、错误信息泄露风险。

## 验收

1. 所有错误处理都返回 `Result`，字段结构固定为 `code`、`message`、`data`。
2. 业务异常能映射为表中的 HTTP 状态与业务码。
3. 未知异常不会把类名、SQL、堆栈或配置内容返回给客户端。
4. 至少有单元或 Web 层测试覆盖一个业务异常和一个未知异常。

## 不做

不新增具体业务规则，不修改用户表，不做国际化错误文案，不实现前端错误弹窗。
