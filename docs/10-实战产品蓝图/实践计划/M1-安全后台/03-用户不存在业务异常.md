# M1-03：用户不存在业务异常

状态：**待开始**  前置：M1-02 已完成

返回 [M1 任务列表](README.md)。

## 目标

把「用户不存在」从 Controller 中的条件表达式或布尔返回值升级为可复用的业务异常。业务规则由 Service 表达，统一异常处理负责把它转换为 HTTP 404 和 `Result.fail(40400, ...)`。

## 范围

- 新增语义明确的业务异常类型。
- 在 Service 提供查询必存在用户的方法。
- 将 `GET /api/users/{id}` 改为使用该方法。
- 更新前先确认目标用户存在；不存在时不再返回成功响应中的 `false`，而是返回 40400。
- 在全局异常处理器中映射为 40400。

## 学习点

Controller、Service、异常处理器的职责边界；HTTP 状态码与业务错误码的配合。

## 验收

1. 查询或更新不存在 ID 都返回 HTTP 404 和业务码 40400。
2. Controller 不再自己拼装「用户不存在」失败响应，也不把资源缺失伪装成成功响应中的 `false`。
3. 已存在用户的查询和更新行为不变，成功与失败分支都有测试。

## 不做

不改删除不存在时的语义；不建立复杂异常层级；不扩展错误码枚举；不在本卡提前引入更新 DTO 与更新参数校验。
