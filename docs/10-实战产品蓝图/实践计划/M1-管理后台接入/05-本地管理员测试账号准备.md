# M1-C-05：本地管理员测试账号准备

返回 [实践计划与进度](../README.md)。

## 目标

为管理后台用户列表提供可复现的本地管理员验收条件，而不是依赖开发者手工修改数据库后却没有记录。

## 范围

- 明确本地开发环境中管理员账号的准备流程、角色关联和验证方式。
- 账号密码只允许由本地环境变量或开发说明提供，禁止提交真实凭据或把明文写入前端。
- 验证该账号登录后请求 `GET /users` 获得 200。

## 学习点

开发数据准备、RBAC 关系、测试前置与密钥边界。

## 验收

1. 新成员按文档可获得一个本地 ADMIN 测试账号，不需要猜测数据库 SQL。
2. 该账号可登录并取得访问 `/users` 的权限；普通账号继续得到 403。
3. 不改变公开注册默认 USER 的安全规则，也不新增角色管理 API。
4. 后端与前端受影响验证命令均通过。

## 不做

不提交真实密码、不在生产自动创建管理员、不做用户角色分配界面。

- 前端无代码改动，`typecheck` / `lint` / `build` 复跑通过。
- 实现物：
  - `config/LocalAdminProperties`：绑定 `app.local-admin.*`（默认留空 = 关闭），`@AssertTrue` 拒绝半配置（只填用户名或只填密码时启动报错），`isEnabled()` 判定引导开关。
  - `config/LocalAdminInitializer`：`ApplicationRunner` 在应用就绪后执行一次；未配置即静默返回，**生产环境不设置环境变量就不会创建任何管理员**；日志只记用户名与「新建/复用」，密码绝不入日志。
  - `UserService.ensureLocalAdmin` + `bindAdminRoleIfAbsent`：账号不存在时按注册同规则创建（BCrypt、状态正常、展示名用登录名、占位邮箱 `<username>@local.test`），已存在时只补缺失的 ADMIN 关联；只绑 ADMIN 角色保持最小权限；`@Transactional` 保证建号与绑角色原子。
  - `UserRoleMapper.countByUserIdAndRoleId`：复合主键关联表的显式 SQL 存在性查询（该 Mapper 不继承 BaseMapper 的既有模式），支撑幂等绑定。
  - `application.yml` 的 `app.local-admin` 段：`BOOT_ADMIN_USERNAME` / `BOOT_ADMIN_PASSWORD` 环境变量注入，默认空。
  - `boot-server/README.md` 新增「本地管理员测试账号（M1-C-05）」一节：环境变量用法、行为说明（成对提供 / 幂等 / 生产不设即不创建）与 curl 验证命令——新成员按文档即可获得 ADMIN 账号，无需猜测数据库 SQL。
- 真实环境验证（本地 8082）：首次启动日志「已创建并绑定 ADMIN 角色」；`boot-admin` 登录后 `GET /api/users` 得 HTTP 200 + `code:0` 真实列表；普通 USER（guard03）同一接口仍 HTTP 403 + `40300`；**二次启动日志「已存在，确认 ADMIN 角色关联」且登录授权结果不变**（幂等实证）。
- 安全边界保持：公开注册仍默认绑定 USER 角色（既有测试回归通过），未新增任何角色管理 API，引导密码只经 BCrypt 落库、不进仓库与日志。
