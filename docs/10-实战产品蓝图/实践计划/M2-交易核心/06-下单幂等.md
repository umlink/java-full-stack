# M2-06：下单幂等

返回 [实践计划与进度](../README.md)。

## 目标

同一用户携带同一幂等键的重复下单请求不重复创建订单。

## 范围

- 下单请求必填 `idempotencyKey`，长度为 1 至 64 个 ASCII 可见字符；为空、超长或含控制字符返回 400/40000。
- t_order 增加 `user_id + idempotency_key` 唯一索引，并持久化不可逆的 `request_fingerprint`。
- 请求指纹由已通过 M2-05 校验的下单语义生成：以当前用户 ID 和按 SKU ID 排序后的「SKU ID + 数量」列表构造规范化数据，再计算 SHA-256。不得直接哈希原始 JSON，以免字段顺序或数组顺序造成同义请求误判。
- 同一用户、同一幂等键、相同指纹：返回首次创建的订单，HTTP 200，且不重复预扣库存。
- 同一用户、同一幂等键、不同指纹：返回 HTTP 409 与 `code:40900`，不得静默重放另一份请求，也不得创建新订单。
- 创建订单的写事务与唯一键冲突后的回查必须分开：写入尝试在可独立回滚的事务中完成；发生唯一键冲突后，在该失败事务之外重新读取首单并比较指纹。禁止在已标记回滚的事务内捕获异常后继续回查或返回成功。

## 学习点

幂等三板斧（token → 唯一索引 → 状态机条件更新）中的唯一索引方案、幂等键设计、并发幂等行为。

## 验收

1. 同键、同请求重复提交只产生一张订单；重放请求返回原单信息，库存预扣只发生一次。
2. 同键、不同 SKU 或数量的请求返回 409/40900，不返回首单作为成功结果。
3. 并发同键同请求仅创建一单，其余均拿到原单；并发同键不同请求仅允许其中一个创建，另一个返回 409/40900。
4. 不带幂等键、空键、超长键或非法字符的请求返回 400/40000。
5. `mvnw.cmd -pl services/user-service -am test` 在 JDK 25 下通过。

## 不做

- 不做预发 token 接口方案（三板斧第一斧，按成本需要再引入）。
- 不做支付/取消场景的幂等（天然由状态机条件更新承担）。
