# ADR-002：Redis Hash 作为购物车权威存储

日期：2026-10-10
状态：已采纳

## 决策

M2.5-01 开启 Redis 购物车模式后，`cart` 模块使用 `bootmall:cart:{userId}` Hash 保存当前购物车。Hash field 是 SKU id，value 只保存购物车条目 id 和数量；商品名、SKU 编码和当前价格仍经 `catalog.api` 查询。购物车采用 30 天滑动 TTL，配置可覆盖。

同一用户的加购、改量和删除由 Redis 原子脚本完成，数量始终位于 1 至 999。Redis 是该模式的唯一写入事实，故障时返回统一系统错误并记录指标，不临时切换到数据库，避免恢复后出现两个互相覆盖的数据源。

原 `t_cart_item` 只用于惰性迁移和显式回退。用户首次访问时，以用户级短租约迁移锁串行执行：Redis 中已有购物车或迁移标记时不重复导入；否则读取旧行、按 SKU 幂等写入 Hash、写入迁移标记，再删除该用户旧行。任一步中断后可安全重试，不存在先删数据库再丢失购物车的窗口。

## 触发信号与备选

M2.5 明确要求购物车高频读写进入 Redis，同时保持用户隔离、数量并发不变式和当前价格语义。

- 继续只用数据库：行为稳定，但没有交付 Redis Hash 购物车，也让每次加购和查看都访问数据库。
- Redis 作为数据库旁路缓存：需要为每次写维护双写一致性，购物车这种高频瞬态聚合会保留数据库写放大。
- Redis 权威存储：读写路径单一，Hash 与原子脚本直接表达用户购物车；代价是 Redis 成为业务依赖，需要持久化、高可用、健康检查和故障指标。

## 影响与回退

部署 Redis 模式时必须启用持久化或托管高可用，并监控 `bootmall.cart.redis.operations`。Redis 不可用期间购物车接口返回 500/50000，商品、订单等其他模块继续运行。

设置 `BOOT_REDIS_CART_ENABLED=false` 可恢复数据库适配器，但已迁移后的新购物车只存在 Redis。回退前应导出 Redis Hash 回写数据库；若接受购物车是可丢弃的瞬态数据，也可清空后让用户重新加购。完成 M3 前保留旧表和 MyBatis 适配器，不执行不可逆 DDL。
